# 配布済み紹介リンクの署名引継ぎ

2026-11-12、本人が `/r/〜` の紹介リンクを現在も使用・配布していると確認した。
従来の `REFERRAL_COOKIE_SECRET` はVercelで再表示できず、新しいキーだけに交換すると
有効な紹介Cookieが無効になる。古いキーをVercel内に残したまま、確認済みのCookieを
新しいキーで署名し直す。紹介者・キャンペーン・取得日時を変えず、最初の紹介を30日間維持する。

**この文書は実装と切替手順。作成時点で本番のキー・署名確認API・DNSは未変更。**

## 環境の対応

| 設定 | 旧Vercel Production | 新Cloudflare Production |
| --- | --- | --- |
| `REFERRAL_COOKIE_SECRET` | 既存値を保持 | 新しい値 |
| `REFERRAL_COOKIE_NEXT_SECRET` | 上記と異なる新しい値 | 設定しない |
| `REFERRAL_MIGRATION_TOKEN` | 移行専用の共通秘密値 | 同じ値 |
| `REFERRAL_MIGRATION_UNTIL` | UTCの固定終了日時 | 同じ日時 |

キー・トークンは暗号化バックアップ後、それぞれのProduction秘密設定へ保存する。
Previewやコード・台帳へ値を入れない。`BOOKING_SOURCE_SECRET` は別機能のため既存値を維持する。

確認先は既存Project `prj_mkbIpIctCuEGUBUb0B2vHrhKn7pI` の固定alias
`https://v0-website-ten-theta-21.vercel.app/api/internal/referral/verify`。
2026-11-12にProjectとの対応・ルートの公開到達性を確認した。
任意の転送先やリクエスト値のURLにはCookie・トークンを送らない。

## 切替順序

1. 合成データで署名・有効期限・予約への引継ぎ・障害時の動作を検証する。
2. 新しい署名キーと移行専用トークンを生成し、暗号化バックアップを検証する。
3. Vercel Productionに新しい設定を追加する。既存の古い署名キーは変更しない。
   終了日時は、旧キーによる最終発行が止まってから30日と時計誤差の5分以上を含める。
   設定時から31日を超える期限は拒否する。再デプロイで期限を延ばさない。
4. 検証済みPRを反映し、独自ドメインと固定aliasが新しい同一コミットに向くことを確認する。
   新規紹介が新キーで署名されること、旧署名の紹介が元の内容・残り時間で引き継がれることを確認する。
   実際の予約・メール・LINE送信は確認目的で作成しない。
5. 旧キーの最終発行停止時刻、固定終了日時、Vercelを残す期間と費用、復旧対象deploymentを台帳に記録する。
6. Cloudflareに新キー・トークン・同じ終了日時を設定し、HTTP実行環境でも照合する。
   キー欠落、古いaliasへの接続不可、時刻不整合があればDNSを切り替えない。
7. DNS切替後も終了日時まで旧Vercel Project・固定alias・キーを維持する。
   新しいCookieはCloudflare内で確認し、旧署名だけ旧Vercelで認証付き検証する。
8. 最終旧Cookieの有効期限経過と新環境の運用を確認した後、移行API・設定・旧環境の削除を別途実施する。
   終了日時を過ぎるとAPIは404となり、Cloudflareからも旧環境を呼ばなくなる。

## 失敗時の挙動

- 新しいキーの署名はローカルで検証する。形式不正・期限切れは外部照合しない。
- 旧環境の署名確認APIはVercel Productionのみ。CloudflareやPreviewでは404。
  Bearer認証、4KBの本文制限、固定終了日時を必須にし、応答を保存しない。
- APIは古いキーそのものを返さない。古い署名が正しいときだけ、新しい署名を返す。
  Cloudflare側も新しい署名と元の紹介内容の一致を検証する。
- 通信・設定・応答の障害時、`/r/〜` は既存Cookieを上書きせず通常のページへ移動する。
  予約はGAS送信前に503を返し、紹介報酬情報を失った状態で保存しない。
- 署名が正しくないと確認できたCookieは紹介なしとして扱う。利用者POST内の紹介情報は信用しない。
- 再署名時も有効期限は元の `acquiredAt + 30日`。新しく30日を付け直さない。

旧Vercel停止前には、他サイトの配布済み `vercel.app` QR等の残存依存も別に確認する。
