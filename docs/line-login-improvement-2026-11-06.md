# LINEログイン改善（実装・公開前確認）

ユーザーから、Instagram → ホームページという入口を維持したまま、顧客が簡単にLINEで認証できる仕組みの実装を依頼された。本番反映前の変更として作成。

## 予約者に見える変更

- スマートフォンで、プラン・日付以外をまだ入力していない場合、「LINEアプリで予約を続ける」を表示。通常のHTTPSリンクで公式LIFF URLを開き、認証後に同じサイトの予約フォームをLINE内に表示する。「このブラウザでLINEログイン」も選べる。
- プランと日付、言語、既存のUTMと署名付き集客経由は引き継ぐ。氏名・電話番号・参加者情報、OAuthパラメータ、IDトークン、URLのhashはリンクに含めない。
- 日時の詳細・人数・連絡先などの入力がある場合はアプリ切替リンクを出さず、同じブラウザに戻る従来のLIFFログインを利用する。認証を開始する直前にも下書きを同期保存する。保存に失敗した場合、入力を失う遷移を止める。
- 紹介報酬のHttpOnly Cookieがある場合も、Cookieを別ブラウザへ移せないため従来のログインを維持する。Cookie値はクライアントへ渡さない。
- LINEが開かない場合の案内をボタンの近くに追加。友だち追加の案内は、日本語フォームでは認証後と予約完了後に表示する。
- 日本語・英語・韓国語・繁体字のフォームに同じ入口・入力保護を適用。

## 認証と環境

- LIFF SDKを2.28.0から2.31.2へ更新・固定。lockfileの変更はLIFF関連パッケージのみ。
- 表示用プロフィールを有効期限内のIDトークンから取得し、追加のgetProfile通信が失敗しただけでログアウトさせない。予約API側のLINEによるIDトークン検証は維持。
- LIFF内ではliff.loginを呼ばず、SDKの初期化による認証を利用する。外部ブラウザの通常ログインは引き続きliff.loginを使用し、OAuth URLやstateの独自実装は追加しない。
- LINE設定・本番環境変数・GAS・通知先・予約制限には変更なし。
- 紹介Cookieの判定により4言語の予約ページは動的描画となる。国際版はマウント後に下書きを読み、サーバー描画との不一致を防ぐ。
- Vercel Previewでは画面に確認用と表示し、LINEログインの開始と予約送信をUIで止める。本番LIFFのエンドポイントは本番サイトのため、別ドメインのプレビューを認証往復の検証には使わない。

## 確認範囲

- 自動テスト：有効・無効・期限切れトークン、個人情報と認証パラメータの除外、言語とプラン・日付・集客経由の継続、入力済み項目の保護を確認。既存の予約APIの認証・予約制限・料金のテストも実行。
- lint、TypeScript、本番向けビルドを確認。
- Chromeの390px幅でフォーム・ログイン案内を確認。実データではない氏名の下書き復元を確認。予約送信・通知は行わない。
- 未確認：iPhone/Androidの実機でのInstagram・Safari・ChromeからのLINEアプリ起動、初回同意、認証後の復帰。OS/WebViewの制限によりアプリ起動を保証するものではない。
- 未確認：LINE Developersコンソールの公式アカウント紐付け・友だち追加オプション。管理者ログインが必要。今回は設定変更していない。

## 公開後の確認・切り戻し

本番反映は別途行う。既存GitHub → Vercel構成を維持する。本番へ反映したら、4言語の画面とSDKバージョン、LINE認証→元の選択内容の復帰を実機で確認する。予約送信はこの確認には不要。

問題がある場合はこの変更をrevertする。公開先やLINE設定の変更はない。
